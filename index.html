Building an AI Assisted Triage Layer for Data Subject Requests

A GDPR request classifier, and where it deliberately stops

25 September 2026 · 6 min read · Published on Medium

When someone exercises their GDPR rights the clock starts immediately, and the hard part is rarely the law — it is reading a steady stream of messy, real-world messages fast enough to meet a one-month deadline. This piece walks through the triage tool I built for that first step: how it maps everyday wording to the right the request most plausibly engages, why it stops at a suggestion rather than a decision, and the safeguards — mandatory human sign-off, data minimisation, an audit log and a DPIA before any real scale — that keep the data protection officer accountable rather than the algorithm.

RAG Compliance Chatbot

A retrieval-augmented chatbot that answers natural-language questions about AI regulation, with the source passages cited back to the reader.

Key results
Documents indexed3 frameworks
RetrievalFAISS vector similarity
StatusLive and publicly usable
How it works

Source documents — the EU AI Act (Regulation EU 2024/1689), the NIST Cybersecurity Framework 2.0 and the NIST AI Risk Management Framework 1.0 — are loaded, cleaned and split into chunks, embedded with a Hugging Face sentence-transformer (all-MiniLM-L6-v2) and stored in a FAISS vector index.

At query time the user's question is matched against the index and the retrieved chunks are passed to GPT-OSS 120B via the Groq API, which composes a plain-English answer with references so the reader can verify the underlying text.

Deployed publicly on Streamlit Community Cloud.

GDPR Request Classifier

Triages incoming data-subject requests, maps each one to the relevant GDPR article and recommends the next compliance action.

Key results
GDPR articles mapped10 request types
LogicTransparent and rule-based
StatusLive and publicly usable
How it works

Transparent, rule-based classification covers ten GDPR topics, including the right of access (Article 15), rectification (Article 16), erasure (Article 17), portability (Article 20), automated decision-making (Article 22) and personal data breach notification (Article 33).

Each classification returns a request type, the mapped article, a priority level with critical handling for suspected breaches, and a recommended action. Recent history is displayed in the interface and can be exported to CSV by authorised demo users.

Built with privacy-by-design in mind: input validation, lightweight application security controls and no collection of real personal data.

2026 World Cup Predictor

Predicts the outcome of any international football fixture using an XGBoost classifier trained on more than 25,000 historical matches.

Key results
Training data25,000+ matches
Test accuracy60.24% (time-based split)
Baseline50.58% form-only model
How it works

Match data from 2000 to 2026 is cleaned and engineered into features covering recent form with exponential time-decay weighting, average goals, win rate, FIFA and Elo ratings, head-to-head record, neutral-venue status and World Cup shot, possession and discipline statistics.

The model is trained with a time-based split — fitted on matches before 2021 and tested on 2021–2026 — so the reported accuracy is an honest out-of-sample figure rather than a leaked one.

Accuracy improved from 50.58% on a form-only baseline to 60.24% after adding rankings, head-to-head records, Elo ratings and time-decay weighting.

Radiology Report Summariser

Fine-tunes a T5 transformer to turn the free-text findings of a chest X-ray report into a short radiology impression, served through a REST API.

Key results
ROUGE-1 F10.450 on 543 test reports
ModelT5-small, fine-tuned
DeploymentDocker on Fly.io, CI/CD
How it works

Built on the Indiana University chest X-ray collection: the pipeline parses the original XML reports, extracts each report's findings and impression, cleans them and makes an 80/20 split into 2,169 training and 543 test reports.

google-t5/t5-small was fine-tuned as a sequence-to-sequence model for two epochs (learning rate 5e-5, inputs up to 512 tokens), and impressions are generated with four-beam search.

Evaluated with ROUGE against the radiologists' own impressions across all 543 held-out reports: ROUGE-1 F1 0.450, ROUGE-2 F1 0.343 and ROUGE-L F1 0.446.

Served by FastAPI with a browser interface and a POST /get_summary endpoint, containerised with Docker and deployed to Fly.io in London, with every push to main deployed automatically by GitHub Actions. A research prototype, not a clinical tool.

Visual Clothing Recommender

Upload a photo of a garment and get back the five most visually similar items from a retail catalogue, ranked by CLIP image similarity.

Key results
ModelCLIP ViT-B/32 image encoder
Catalogue searched5,017 clothing images
Top match similarity0.964 cosine
How it works

A cleaning step validates every catalogue image and removes exact duplicates by file hash. Each image is then encoded with OpenAI's pre-trained CLIP ViT-B/32 model, and the embeddings are saved alongside their image paths so the catalogue never has to be re-processed at query time.

An uploaded photo is encoded the same way and compared with every catalogue embedding by cosine similarity; the five closest items are returned with their scores. The deployed demo searches a 5,017-image catalogue.

Matching is purely visual, so it can rank items that share a colour or background but differ in garment type. Planned improvements include filtering on product metadata such as category and price, fine-tuning on fashion imagery, and FAISS search for larger catalogues.

EU AI Act Risk Checker

A REST API and web interface that screens an AI use case against the EU AI Act risk tiers and returns a structured, explainable verdict.

Key results
Risk tiersUnacceptable to Minimal
OutputStructured, explainable JSON
ControlsValidation, limits, audit log
How it works

Classifies a described use case as Unacceptable, High, Limited or Minimal risk and returns structured JSON containing the risk level, the EU AI Act category, a one-line verdict, the trigger that matched, a recommended next action and a short explanation of the reasoning.

Governance controls are built into the demo: input validation and sanitisation, per-session rate limiting, and audit logging that records a hash of the input rather than the raw text, so activity is traceable without storing sensitive content.

Sentiment Analysis API

A production-style REST service that classifies text as positive or negative using a fine-tuned DistilBERT model.

Key results
Positive example99.99% confidence
Negative example99.98% confidence
Known limitationNo neutral class
How it works

DistilBERT (distilbert-base-uncased-finetuned-sst-2-english) is loaded through Hugging Face Transformers and exposed via a FastAPI /predict endpoint served by Uvicorn, returning a label and a confidence score.

The project documents its own limitation honestly: because the model has only two classes, a neutral sentence such as “The package arrived on Tuesday” is forced into the nearest match and scores 98.30% positive. Understanding and communicating that failure mode matters as much as the accuracy figure.

CIFAR-10 CNN & API

A convolutional neural network trained on CIFAR-10, benchmarked against a dense baseline and served through a REST API.

Key results
CNN validation accuracy63.4%
Dense baseline43.0%
Improvement+20.4 percentage points
How it works

Two models were trained and compared. The dense baseline flattens each image and reaches 43.0% validation accuracy; the CNN — Conv2D(32) → MaxPooling → Conv2D(64) → MaxPooling → Conv2D(128) → Dense(128) with dropout — reaches 63.4%, an improvement of 20.4 percentage points.

The trained model is served by a FastAPI /predict endpoint. Real-world testing showed 99.54% confidence on a car and 96.90% on an aeroplane, while a container ship was misclassified as a truck — at CIFAR-10's 32×32 resolution a boxy hull and a lorry are genuinely hard to separate.

CV Screener API

Scores how well a candidate CV matches a job description using semantic sentence embeddings rather than keyword counting.

Key results
Strong match79.6%
Moderate match50.23%
Weak match23.99%
How it works

The job description and the CV are each encoded into vector embeddings with sentence-transformers (all-MiniLM-L6-v2), and cosine similarity between the two vectors produces the match score — so wording that means the same thing scores closely even when the exact terms differ.

Scored against a data scientist job description, a matching data science CV returned 79.6%, a software developer CV 50.23% and an unrelated chef CV 23.99%.
