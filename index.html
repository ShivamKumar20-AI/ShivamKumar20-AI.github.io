Building an AI Assisted Triage Layer for Data Subject Requests

A GDPR request classifier, and where it deliberately stops

25 September 2026 · 6 min read · Published on Medium

When someone exercises their GDPR rights the clock starts immediately, and the hard part is rarely the law — it is reading a steady stream of messy, real-world messages fast enough to meet a one-month deadline. This piece walks through the triage tool I built for that first step: how it maps everyday wording to the right the request most plausibly engages, why it stops at a suggestion rather than a decision, and the safeguards — mandatory human sign-off, data minimisation, an audit log and a DPIA before any real scale — that keep the data protection officer accountable rather than the algorithm.

RAG Compliance Chatbot

A retrieval-augmented generation chatbot that answers questions over long regulatory documents using LangChain, FAISS, embeddings and a Groq-hosted LLM.

Key results
Documents indexed3 frameworks
RetrievalFAISS vector similarity
ModelGPT-OSS 120B via Groq
Problem

Long regulatory documents are difficult to search quickly and accurately.

Approach

A RAG pipeline that chunks the source documents, embeds them with a Hugging Face sentence-transformer (all-MiniLM-L6-v2), retrieves the relevant passages with FAISS vector search, and passes them to a Groq-hosted LLM to generate an answer grounded in the retrieved text.

What it demonstrates

Document retrieval, vector search, prompt construction, grounded LLM output, source citation and an interactive Streamlit interface.

Deployment

Streamlit app with a public live demo. Built in Python; the app is Streamlit end to end rather than a separate API service.

Limitations and next steps

No evaluation dataset or retrieval-quality metrics yet. Next steps: a labelled question set, retrieval metrics, metadata filtering, structured logging and privacy controls for enterprise use.

World Cup Predictor

A classical machine-learning application that predicts football match outcomes from team form, FIFA rankings, Elo ratings, head-to-head history, World Cup performance and match statistics.

Key results
Training data25,000+ matches
Test accuracy60.24% (time-based split)
Baseline50.58% form-only model
Problem

Match results are hard to predict because they depend on team strength, recent form, historical performance and unpredictable match events.

Approach

A multi-class classifier for home win, draw and away win, trained on 25,000+ international matches. Engineered features cover rolling form with exponential time decay, goals scored and conceded, win rate, FIFA rank, Elo rating, head-to-head record, neutral-venue status, and World Cup shots, possession and discipline.

What it demonstrates

Classical ML, time-aware data preparation so the model is never trained on future matches, feature engineering, probability output, error analysis and deployment.

Deployment

Interactive Streamlit application with live 2026 fixture data.

Limitations and next steps

Accuracy is 60.24% on a time-based split, against 50.58% for a form-only baseline; draws remain the hardest class. The repository includes an error-analysis notebook covering upsets, draw failures and close matches. Next steps: lineup and injury data, expected-goals features, probability calibration and a dedicated draw model.

Resume Screener

A FastAPI service that scores how well a CV matches a job description using sentence-transformer embeddings and cosine similarity.

Key results
Strong match79.6%
Moderate match50.23%
Weak match23.99%
Problem

Screening a CV against a job description by hand is slow and inconsistent.

Approach

Both the CV and the job description are encoded into semantic embeddings with sentence-transformers (all-MiniLM-L6-v2). Cosine similarity between the two vectors produces a match score, returned from a FastAPI POST /screen endpoint, so wording that means the same thing scores closely even when the exact terms differ.

What it demonstrates

Embedding-based NLP, semantic similarity, API design and awareness of where automated scoring should not be trusted.

Deployment

Runs locally as a FastAPI service; there is no public demo. Deploying the API is a potential next step.

Limitations and next steps

Scored against a data scientist job description, a matching CV returned 79.6%, a software developer CV 50.23% and an unrelated chef CV 23.99%. There is no labelled evaluation set yet. Next steps: compare scores with human ratings, surface the matching skills behind a score, and assess fairness risks before any real use.

Radiology Report Summariser

A transformer-based NLP prototype that turns the free-text findings of a chest X-ray report into a concise impression, using a fine-tuned T5 model.

Key results
ROUGE-1 F10.450 on 543 test reports
ModelT5-small, fine-tuned
DeploymentDocker on Fly.io, CI/CD

Technical demonstration only. Not a medical device and not a clinical decision-support tool.

Problem

Radiology findings are long and variable, while the impression that summarises them is what gets read first.

Approach

google-t5/t5-small was fine-tuned as a sequence-to-sequence model on 2,169 paired findings and impressions from the Indiana University chest X-ray collection, for two epochs at a learning rate of 5e-5, generating with four-beam search.

What it demonstrates

Transformer fine-tuning, sequence-to-sequence summarisation, ROUGE evaluation, containerisation and automated deployment.

Deployment

FastAPI with a browser interface and a POST /get_summary endpoint, containerised with Docker and deployed to Fly.io in London, with deployment wired to GitHub Actions.

Limitations and next steps

ROUGE-1 F1 is 0.450 across all 543 held-out reports (ROUGE-2 0.343, ROUGE-L 0.446). The model leans towards reporting a normal study and misses consolidation: of 65 test reports whose impression mentions consolidation, pneumonia, airspace disease or an infiltrate, only 15 generated impressions mention any of those. Next steps: balance the training data, measure sensitivity for specific findings alongside ROUGE, and try a larger or clinically pre-trained model.

GDPR Request Classifier

Triages incoming data-subject requests, maps each to the relevant GDPR article and recommends the next action.

Key results
GDPR articles mapped10 request types
LogicTransparent and rule-based
StatusLive and publicly usable
How it works

Transparent, rule-based classification covers ten request types across GDPR Articles 13 and 14, 15, 16, 17, 18, 20, 21, 22, 33 and 77, each with a default priority.

A request that trips several rules is reported under the most urgent one, so a message that both asks for a copy of personal data and discloses a breach is treated as a breach — Article 33 carries a 72-hour deadline that Article 15's 30 days does not.

Every classification is written to a SQLite log, and input validation rejects malformed or hostile input. I wrote about the design in the article below.

Visual Clothing Recommender

Upload a photo of a garment and get the five most visually similar items from a retail catalogue, ranked by CLIP image similarity.

Key results
ModelCLIP ViT-B/32 image encoder
Catalogue searched5,017 clothing images
Top match similarity0.964 cosine
How it works

Catalogue images are validated, de-duplicated by file hash, and encoded with OpenAI's pre-trained CLIP ViT-B/32. The embeddings are saved with their image paths so the catalogue is never re-processed at query time.

An uploaded photo is encoded the same way and compared with every catalogue embedding by cosine similarity. The deployed demo searches a 5,017-image catalogue.

Matching is purely visual, so it can rank items sharing a colour or background but differing in garment type. Next steps: filter on product metadata, fine-tune on fashion imagery, and use FAISS for larger catalogues.

Sentiment Analysis API

A production-style REST service that classifies text as positive or negative using a fine-tuned DistilBERT model.

Key results
Positive example99.99% confidence
Negative example99.98% confidence
Known limitationNo neutral class
How it works

DistilBERT (distilbert-base-uncased-finetuned-sst-2-english) is loaded through Hugging Face Transformers and exposed via a FastAPI /predict endpoint served by Uvicorn, returning a label and a confidence score.

The project documents its own limitation: because the model has only two classes, a neutral sentence such as “The package arrived on Tuesday” is forced into the nearest match and scores 98.30% positive.

CIFAR-10 CNN & API

A convolutional neural network trained on CIFAR-10, benchmarked against a dense baseline and served through a REST API.

Key results
CNN validation accuracy63.4%
Dense baseline43.0%
Improvement+20.4 percentage points
How it works

Two models were trained and compared. The dense baseline flattens each image and reaches 43.0% validation accuracy; the CNN — Conv2D(32) → MaxPooling → Conv2D(64) → MaxPooling → Conv2D(128) → Dense(128) with dropout — reaches 63.4%, an improvement of 20.4 percentage points.

The trained model is served by a FastAPI /predict endpoint. Real-world testing showed 99.54% confidence on a car and 96.90% on an aeroplane, while a container ship was misclassified as a truck — at CIFAR-10's 32×32 resolution a boxy hull and a lorry are genuinely hard to separate.

Newsgroups Text Classifier

Classifies newsgroup posts into topic categories with a TF-IDF and logistic regression pipeline.

Key results
Dataset20 Newsgroups, 4 categories
PipelineTF-IDF + logistic regression
OutputsSaved model, confusion matrix
How it works

Uses a four-category subset of scikit-learn's 20 Newsgroups dataset: alt.atheism, talk.religion.misc, comp.graphics and sci.space.

The pipeline vectorises the text with TF-IDF and fits a logistic regression classifier, with a standalone training script, a notebook walkthrough, a saved model artefact and a confusion matrix of the results.

A deliberately simple baseline: it shows the classical NLP groundwork that transformer models are measured against.
